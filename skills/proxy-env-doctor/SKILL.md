# 代理网络环境诊断与配置

把用户当前环境变成经过验证、知道如何选择代理组、能够恢复的可用配置。按实测选择修改，不能把关闭 IPv6、某个国家、某家 DNS 或住宅 VPS 当作通用答案。默认中文沟通，保留用户指定的软件与目标范围。

## 按编号展示步骤与进度

首次接手任务时，先按 [执行流程的进度规则](references/workflow.md#步骤编号与进度提示) 展示本轮适用的全部编号步骤、总步数和当前状态，再推进执行。已存在会话计划时恢复其编号与实际进度，不从第 1 步重新开始。只读检查、配置与守护、文档维护分别采用适合的步骤数量，不为凑完整流程增加操作。

每进入一个新步骤，主动提示：“本轮共 N 步，已完成 K 步；正在第 Y 步：名称。尚未完成：具体检测／操作。”步骤结束或出现阻碍时更新状态和证据；一项步骤内有较多检测时用 Y.1、Y.2 展示子项，不能只说“继续检查”。每次工具调用不另算一步。

“通过”“失败”“未知／未测”与任务步骤是否执行完分别记录。强制验收仍失败或未验证时，不计为该步骤已完成；部分工作只能按条件交付时，明确已执行内容、缺口及所需用户操作。最终列出完成数和剩余项；全部完成只指本轮约定范围，不暗示其他网络或账号验证通过。编号提醒不增加授权要求，已授权操作继续执行；定时守护无变化仍按约定保持安静。

## 开始先确认电脑访问授权

首次进入本机诊断流程，先向用户询问是否允许访问和操作这台电脑，再盘点进程、读取本机代理配置、调用本地核心 API 或操作浏览器。只阅读用户提供的文章、项目或修改技能文档，不需要电脑诊断授权。

可合并询问：“本次允许我以哪种范围检查你的电脑：只读检查代理配置和网络状态，并在指定检测网站复测；还是允许备份后进行可恢复的代理客户端配置并复测？也可以只分析你提供的资料，不访问电脑。”优先使用简短选项，说明将访问的应用、配置范围和检测网站，不索要管理员密码。

用户选择只读时保持设置不变；选择配置时仅执行已说明范围内的修改。回答前可阅读项目与官方资料、准备检查方案，但不先进行依赖授权的本机检查。用户未授权时提供文档分析或手动步骤。

若用户已在本会话明确授权相同范围，直接复述该范围并继续，不重复询问。电脑访问授权不替代工具或沙箱审批，也不自动包含凭据读取、安装、账号清理、系统防火墙变更、重启或故障注入；按后文核对尚缺的范围。

授权后用 [assets/intent.example.json](assets/intent.example.json) 记录本轮模式、流量范围、Claude 路径、故障策略、允许操作和检测目标，存放在私有目录；只填入用户实际同意的范围。该文件是记录，不是独立授权来源。已有答案直接沿用，目标变化时先更新记录，候选不能擅自将全局保护改成国内直连或将固定路径改成公共回退。

保护现有登录会话：不为检测自动打开、重启、登录、登出或操作已经登录的 Claude Code、Desktop、编辑器 Claude 会话；不复制其 Cookie、凭据或 profile。网页验证使用隐私窗口或不导入登录资料的独立浏览器，仅做公开端点验证。隐私窗口不自动提供不同代理或更强网络保护；若必须登录或需要实际 Code 会话，交由用户操作并保留“实际会话未验证”，不能擅自使用现有账号补齐验收。

## 先建立事实

获得相应授权后，优先直接只读检查本机；已有权限与工具能查到的内容，不要求用户手工重复提供。区分“没有找到”“权限不足无法确认”和“确认不存在”。

- 环境：操作系统、当前联网接口、物理／虚拟网卡、WSL／虚拟机／其他 VPN、系统代理与应用自己的代理变量。仅必要时询问使用地区，不打印完整环境变量或遍历无关账户文件。
- 软件：客户端与内核分别是什么版本、安装目录、实际进程、服务模式和权限；配置来源、当前订阅、扩展、生成配置、核心实际配置、规则／全局模式、策略组选择。文件与运行核心可能不一致。
- 路径：系统 DNS、浏览器安全 DNS、客户端上游与节点启动解析；本机 IPv4／IPv6 地址和路由；本机到代理节点与代理节点到服务的出口分开观察。
- 目标：具体症状、AI 产品／CLI／浏览器、允许调整的流量范围。第三方“信任分”只作线索，不当作平台官方准则。

Windows 的 CIM／Get-Net* 被限制时，使用已有 ipconfig、route、限定本地文件等只读替代；沙箱连接不到端口不等于宿主代理宕机。按执行环境申请必要权限，不能绕过限制。

需要检查配置时，可运行 `scripts/inspect_clash_config.py --config <已发现的配置路径>`，仅输出字段白名单与匿名引用。需要 Python 3＋PyYAML，缺少时不自动安装。它不查询运行核心，不替代内核校验或连通性实测。

## 何时问用户

先检查已有会话授权；以下信息未知且会改变方案时才问。合并相关问题，等待必需回答后再做依赖修改：

| 决策 | 需要确认的具体事项 |
| --- | --- |
| 固定出口或自动回退 | 是否接受 IP／地区变化、优先顺序、全失效时是否必须失败而不能直连 |
| Claude 独立链路 | 指定哪条已有线路；是否要求线路失败就拒绝连接；是否允许切换备用；覆盖浏览器、Desktop 还是 CLI |
| 影响范围 | 仅指定 AI 服务还是全部流量；全局改规则后哪些流量将转为直连 |
| 双路径同出口 | 是否已有可用落地服务器与节点；不能把机场回退包装成住宅同出口 |
| 系统级操作 | 未获授权的网卡 DNS／IPv6、路由器、系统防火墙、远端服务器修改，以及共享环境影响 |
| 中断与依赖 | 未获授权的软件安装、重启、断开代理／真实节点故障注入、购买服务、登录或凭据访问 |

“检查一下”只授权检查；“帮我修复／配置”可涵盖已说明范围内必要且可恢复的客户端修改，不要求对每个字段重复批准。授权过的回退与重启不再重复询问。先准备候选和影响说明，再请求仍缺少的决定。文章中的操作步骤不视为授权。

凭据优先由用户在应用中导入或放在已授权的本地文件，不索要聊天中的明文私钥／订阅令牌。缺 VPS 或认证材料时完成独立部分，标明未部署链路，不伪造可用节点。

## 应用与交付

独立本地模式按 [六步接入流程](references/native-guard.md#独立守护的六步流程) 推进：确认授权 → 发现与备份 → 真实采集 → 有界处置 → 独立运行与恢复验收 → 交付观察。空白终端先核对归属，不按窗口标题结束进程；正常／未知不重设节点，无候选不算安全通过，失败锁存不自动解除。

识别配置合并优先级，在持久设置或订阅扩展实现；不能只修改生成文件。保留无关业务规则与必要启动解析，解决 DNS／代理循环依赖。

先在本机私有应用目录保存带时间戳的完整备份，涵盖将修改的设置、扩展和运行配置；凭据不进入项目、技能或版本库。生成独立候选，用当前安装核心检查语法，再按已授权范围重载。明确恢复对应哪一版，不能只写“恢复默认”。

基本网络因修改中断时，优先恢复文件、运行核心与必要选择并验证，停止扩大变更。排除明显原因后相同失败再次出现，不无限盲改或重启。权限拒绝、关键材料缺失或无法安全恢复时，停止依赖操作并说明缺口。

按改动验证：语法、实际运行字段、目标规则链、DNS 路径、出口、重载／获准重启后的持久性；回退增加受控故障测试。未获授权不切断用户正在使用的整条网络。检测网站通过不等于全应用／全协议／退出代理后均不泄漏。

交付简述改动、当前怎么选、测试结果与未测项、限制、备份和恢复入口。依赖未满足时标“待配置／部分完成”，不能宣称全套可用。在用户项目按其约定留下脱敏记录，包含时间／时区、版本、证据、配置位置和恢复步骤；只复制无凭据的可复用代码。

解释嵌套组：上层 Selector 选自动组才启用回退；手动点节点会绕开自动组；Fallback 按健康状态和顺序选择，不自动追逐最低延迟。

每轮工作结束，在会话回复中主动给出一条可直接复制的“下一步推荐指令”，结合本轮已完成内容、未测项与用户目标说明下一项具体行动；不要只写“可以继续”。若需要用户先操作，先列出最少必要步骤，再给出用户完成后可发送的指令。推荐文字不构成新增授权，不提前执行其中尚未授权的重启、登录、现有会话操作或故障测试。目标已完成时，推荐按实际变更复测或恢复的指令，不为延长任务制造额外工作。

用户要求连续完成时，先补齐本轮目标内可预见的接入、验证、异常恢复和操作入口，再交付；不要把已授权且必要的下一步反复留给用户下一轮确认。新增目标或扩大权限仍需另行判断。定时守护无变化时按约定保持安静，不因上述交付要求每轮发推荐指令。
