# DNS、IPv6、AI 与回退决策

## DNS／TUN

分清请求是否进入客户端 DNS、选择哪个解析器、到解析器的连接走哪里、业务连接最终走哪里。DoH 加密不等于经代理；TUN 接管不等于上游自动走代理。

- 核对系统 DNS、浏览器 DoH、应用自建 DoH／DoT，以及 nameserver、fallback、nameserver-policy、direct-nameserver。国内递归解析器是线索，不能仅凭地址证明具体绕过路径。
- 对照当前版本检查 TUN、auto-route、接口和 strict-route。Windows 严格路由对多宿主 DNS 有帮助，也可能影响虚拟机；不能称为全系统 kill switch。
- any:53 默认 UDP，需要时补 tcp://any:53。端口 53 接管不会自动截获任意应用的加密 DNS；Windows／macOS 发往局域网 DNS 的自动接管有限制。
- 使用 #策略组时确认组存在、选择符合目标。GLOBAL 只在它当前选择符合目标时才可靠；切规则模式后重新检查。
- 将节点启动解析与普通浏览域名解析分离；保留直连启动解析时说明用途与隐私例外。不要删除必要的订阅特殊策略，也不要让启动解析依赖尚未连通的代理。
- 不为套教程任意切栈、改 MTU 或覆盖所有 DNS。整体替换前保留仍需的局域网过滤、hosts 和特殊策略，说明取舍。

## IPv6 的三个层次

1. 本机／TUN 接管：公网 IPv6 地址、默认路由和绕过证据；链路本地地址不是公网出口。
2. 本机连接代理节点的协议族。
3. 远端代理连接目标的协议族与路由。

域名规则不天然只匹配 A 记录。dns.ipv6=false 控制内置 DNS 的 AAAA 应答，不关闭系统 IPv6；显式地址、自建解析与远端解析要单独评估。顶层 ipv6 的语义按版本核对，不承诺阻断所有 IPv6 请求。

Mihomo 用 YAML `ipv6: false`，不抄 `ipv6 = false`，不混用 V2Ray 的 domainStrategy／ForceIPv4 参数。本机用 IPv4 连接代理后远端仍可用 IPv6。需要限制远端协议时，调整有权控制的远端或选择实测符合目标的节点。

网卡／系统 IPv6 禁用是有条件的排查或用户选择，不是默认动作。记录原绑定与路由，考虑 WSL、企业 VPN 和局域网影响；不为第三方评分修改时区、语言、指纹。

## AI 分流

先确认具体服务与客户端，参考官方网络要求和可审查规则集。需要保护的精确域名／后缀置于可能命中 DIRECT 的规则之前，不依赖宽泛关键词或代理整个 google.com／公共 CDN。

Claude 注意登录、API、更新与 claudeusercontent.com；ChatGPT 注意认证、静态资源、上传和实时通信；Gemini／NotebookLM 注意登录与专用 API；编程工具可能有独立网关／更新端点。云提供商、第三方 MCP、自定义网关按实际地址另补，不保证固定列表永远完整。

共享登录／验证码／CDN 域名会影响其他服务，应说明。国内 AI 是否走海外由目标与原规则决定。记录规则集来源、快照时间及更新方法，不能覆盖用户例外或执行远程脚本。

全局模式跳过逐服务规则。切规则模式前确认流量范围，保留原规则与 MATCH 策略，验证实际命中；不同客户端的 MATCH／FINAL 语法不混抄。

Claude 要求独立指定链路时，按 [claude-dedicated-route.md](claude-dedicated-route.md) 单独设计故障策略和入站。用户要求全局模式或全流量保护时，不自行切回国内直连分流，也不将共用 GLOBAL 描述为 Claude 专用路径。

## 两种回退

| 类型 | 条件 | 限制 |
| --- | --- | --- |
| 同地区机场 fallback | 用户接受 IP 变化，有多个经实测候选 | 不保证独立运营商、固定出口、账号可用性 |
| 双路径同落地 | 已有落地；直达或经机场入口到同一落地 | 本地宽带、落地、出口仍是共同故障点 |

验证候选实际国家、目标出口与可达性再定顺序；节点名不证明住宅／地区属性。相同机场或出口记为共同故障域。不能自行买 VPS 或用假节点填补缺口。

fallback 显式列优先顺序，按需设置 url、interval、timeout、lazy、expected-status。204 探测可要求 204，但通用探测不证明业务可用；401／403 不自动等于断网，任意 HTTP 响应也不等于业务正常。

受保护出口组不意外 include-all、加入 DIRECT／跨区候选或不受约束的嵌套组。若要求空组失败，核对版本后显式配置合适 empty-fallback。分清候选为空、候选全失效与退出客户端。已有流式连接不能无缝迁移，应用可能需重试；检测周期不是恢复 SLA。

双路径中将 dialer-proxy 放在备用落地节点，引用机场入口／入口组。最终出口组只含两个落地路径，避免入口组反向引用造成环路。两个落地入站必须已部署并使用一致的最终出站；同一 VPS 地址不证明最终 IPv4／IPv6 出口一致。UDP 逐段验证，udp:true 不证明端到端可用。
