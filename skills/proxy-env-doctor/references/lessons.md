# 已遇到的问题与处理依据

集中维护可复用经验，不存用户真实配置或完整会话。以下记录来自一次 Windows／Clash Verge Rev／Mihomo／Edge 实施，其他环境需要重新验证。详细现场日志保留在使用者本机。

## 检测与路由

| 现象或容易误判的地方 | 经验与处理方式 | 证据边界 |
| --- | --- | --- |
| HTTPS 是代理 IP，国内 STUN 却显示宽带 IP | 分别检查 HTTP 和 STUN 路径；DNS 劫持不自动约束 STUN UDP | 同一浏览器出现过该现象，不能仅凭国外出口判安全 |
| 检测表全部绿色 | 分开记录候选、无候选和超时；没有候选时保持 unknown | 页面文字不等于全协议通过 |
| 把 My IP 当作泄漏候选 | 解析 STUN 结果列，HTTP 标头单独保存为出口参考 | 解析器已有字段隔离测试 |
| 表格改版、缺行、重复或加载中 | 当前解析器严格识别九项服务；不符合则未知并核查 | 不为了维持“通过”而放宽解析规则 |
| 全局模式加了 Claude 域名规则 | 使用专用入口和明确出站，观察实际连接链 | 规则文本不能证明全局模式下独立路由生效 |
| 节点名称不同就认为换了 IP | 验证实际公网出口，候选还需验证地区和可用性 | 本机演练验证过不同 SG 出口，不能推广到所有订阅 |
| 把历史宽带 IP 当作当前宽带 IP | 标注历史来源，不未经授权关代理重新探测 | 基线变化可能造成漏报 |

## 客户端与浏览器

| 现象或容易误判的地方 | 经验与处理方式 | 证据边界 |
| --- | --- | --- |
| UI、生成文件和核心状态不同 | 对照实际核心；持久改动写入正确来源，按授权验证重生成 | 文件写入成功不代表客户端缓存已更新 |
| 找不到 TCP 控制端口 | 发现实际本地管道或接口，正确处理 HTTP 分块与 UTF-8 | 接口名称取决于安装方式和版本，不能硬编码现场值 |
| 浏览器连接中断或标签列表为空 | 盘点连接；在仍连接且已确认的专用实例中绑定或新建检测标签 | 工具要求停止时遵守，不绕过禁止访问 |
| 多个 Edge 实例看起来相同 | 核对实际实例与代理链，不凭窗口标题或同一网址认定 | 排查曾发现普通 GLOBAL 与专用入口两种通道 |
| 隐私窗口就认为流量隔离 | 窗口隐私与路由分别验证，专用 profile 仍需行为复测 | 隐私窗口不保证 WebRTC 或独立代理 |
| PATH 没有 Claude CLI | 区分桌面 Code、CLI、编辑器和远端环境，静态检查安装位置 | 桌面可自带核心；发现安装不授权启动会话 |
| PowerShell 启动脚本受执行策略限制 | 选用正式支持的入口，不为了启动降低系统策略 | 临时本机启动方法不等于通用安装器 |
| 名叫 Claude-Private 就认为是桌面入口 | 读取快捷方式的实际目标和参数，区分 Edge、桌面启动器与 CLI | 本机曾确认同名风格入口实际启动 Edge；未执行快捷方式补测 |
| 系统代理关闭就认为全部直连 | 分开检查运行 TUN、路由与应用显式代理 | 本机曾同时出现系统代理关闭和 TUN 开启；没有实际应用链路时不作安全结论 |

## 暂停、恢复与工程实现

| 现象或容易误判的地方 | 经验与处理方式 | 证据边界 |
| --- | --- | --- |
| REJECT 就认为浏览器完全暂停 | 拒绝入口与进程暂停分别实现和验收；处理该入口旧连接 | 不能证明绕行 UDP 或已提交 I/O 被阻止 |
| 按 msedge.exe 名称批量操作 | 精确 profile／代理参数、父子关系和创建时间；固定句柄防止 PID 重用 | 现场暂停只选中专用实例；其他实例排除另有单元测试 |
| 守护退出就自动恢复浏览器 | 失败暂停应保留；手动 resume 与重新放行分开 | 已测暂停提交后异常退出、独立恢复及重复恢复 |
| 中断后重复换线 | 动作前保存单次意图，中断后进入失败处置，不重放换线 | 原生调用与日志提交之间仍有不确定窗口，需报告核查 |
| 两秒暂停探测当作持续保护 | 探测工具自动恢复；持续暂停需持久日志和恢复入口 | CPU 停止增长不能证明完整网络安全 |
| Windows 默认编码读取节点 JSON 失败 | 明确 UTF-8，异常信息避免打印配置或凭据 | 本机遇到过默认 GBK 解码错误 |
| 原子替换偶发 WinError 5 | 保留原子替换，对短暂权限／共享失败有界重试；持续失败则停止 | 具体持锁软件未确认，不断言是杀毒软件 |
| 测试全绿就认为新手可复现 | 在干净副本上检查公开适配器、安装和真实采集路径 | 私有脚本参与的演练不证明公开仓库独立可部署 |
| 已有守护状态文件就认为定时任务还在 | 检查最后真实采集时间、浏览器和正式任务是否存在；恢复时复用任务或确认缺失后恢复单个任务 | 本机曾发现状态 enabled 但采集过期、原任务不存在；不推断删除原因 |
| 希望固定节点，却把守护组直接点到物理节点 | 用户允许故障备用时，将首选放入有序 Fallback，并让守护组选择该 Fallback | 本机应用后主节点与出口未变；手点物理节点会绕开普通健康回退 |
| 每轮检测都重新选“最好”节点 | 正常／未知结果不重设选择；事件内指定备用后不自动回首选 | 固定顺序回退与按延迟选优是不同策略；供应商仍可能改变同一节点的 IP |
| 桌面预检 ready 就认为账号或全部协议通过 | 区分启动条件、实际新会话链路和旁路子进程；失败先拒绝启动，不操作旧进程 | 本机真实过期拒绝、新采集后预检通过，Claude 未启动；仅 Edge 有原生暂停能力 |

## 可移植实现的新增验证

- 空白 Windows Terminal 不能仅凭目录标题归因于守护；核对进程关系及命令行，后台状态另查。虚拟环境包装进程与实际解释器不必然是两个工作实例；不能按同名进程数批量终止。截图归属未确认时保留该结论，不宣称已修复窗口问题。

- 桌面入口只读取 agent 定时采集文件，会让日常启动被 agent 在线状态卡住；独立需求应由本地服务采集，入口按需刷新，不能靠延长过期阈值掩盖。新运行方式见 [本地守护](native-guard.md)。
- 适配器通过 stdin 的 end 事件开始工作时，execFile 调用方必须显式关闭输入；本机独立采集曾因此出现“页面成功、通道一直超时”，现有真实子进程测试覆盖。
- 后台进程的 PID 可能已被复用；本机曾发现旧记录 PID 对应 conhost，身份检查阻止了误停。停止时核对命令、目录及运行身份，优先运行标识驱动的正常退出。
- Windows 无窗口、脱离控制台与脱离作业对象是不同条件；独立性需要检查实际运行进程，不能把 DETACHED_PROCESS 当作关闭 agent 后存活的证据。

- 控制响应和节点名使用 UTF-8，并用真实回环 HTTP 分块响应做离线验证；不把接口失败当成节点失效。
- 保存探测组原选择时需复制值，不能保留后续会被修改的对象引用；已用失败探测和取消切换测试验证恢复。
- 生成 listener 只绑定 IPv4 回环时，不能允许浏览器配置成 IPv6 回环；schema 及测试现已拒绝这一不匹配。
- 卸载应保留用户安装后新的合法 GLOBAL 选择，文件有后续修改时停止；模拟部署测试验证了这些分支。
- 干净源码副本和新依赖环境只能验证公开代码独立性，不能代替真实新电脑安装、浏览器采集或账号会话验证。

## 如何新增记录

只记录会改变下一次操作的经验。写清症状、适用环境、已核实或仍未知的原因、处理步骤、验证证据及限制。真实案例先去除路径、IP、节点、会话和凭据，再提炼规则。

有更强证据时更新原条目。相同规则只维护一处，执行流程和技能入口链接本文件，避免累积相互矛盾的会话总结。
