# 本地操作、验证与恢复

## 软件与工具

发现实际安装与数据目录，不硬编码本次会话的用户、盘符、订阅 UID。APPDATA 下 Clash 目录只作候选，核对进程、版本与服务核心的实际工作目录。

只取任务需要的工具：现有只读网络命令、curl、已安装核心的 -t、已有格式解析器和可用浏览器。Python／Node 可选，不为排查先装一套软件。若 UI 操作确有必要，使用当时可用的计算机／浏览器工具并遵守其说明；无需假设某个插件必然存在。

只读配置摘要：`python <技能目录>/scripts/inspect_clash_config.py --config <配置文件>`。需要 Python 3＋PyYAML；缺失时用已有解析器或限定字段人工检查，不自动装依赖。proxy-1／group-1 是稳定于该输入的匿名引用，不输出节点名、地址或 DNS URL。DNS 的 UNRESOLVED_ROUTE_OR_INTERFACE 也可能是合法接口，不能据此判配置损坏；策略内容需按授权另作限定字段检查。它不替代核心校验与运行态检查。

## 本地 API

优先已启用的本地受认证接口，不新增公网控制端口或关闭认证。令牌在进程内使用，不回显完整配置、订阅 URL、环境或异常中的凭据。

先读取 /version、/configs 确认目标，再按需读 /proxies、/rules、/connections。连接元数据限测试域名与时间，不导出用户全部浏览活动。多个核心实例时明确选择，不随便取第一个。

Windows 服务的实际命名管道可能与生成文件不同。自行实现 HTTP 时按字节处理 Content-Length、chunked 与 UTF-8，设置连接／读取超时；不无限 ReadToEnd，不把分块正文直接交 JSON 解析。

按当前 API 文档重载。文件不在服务允许目录时，不扩大 SAFE_PATHS 权限；用应用自身重载，或版本支持且已授权时用本地 payload。payload 含完整凭据，不回显、不发送外部。

应用设置可能覆盖扩展字段。应用后核对运行核心与生成文件；必要且已授权时正常重启验证持久性，避免强杀丢失选择。重启后确认当前选中组，而非只看默认值。

## 按改动选择测试

| 层次 | 证据与边界 |
| --- | --- |
| 基线 | 记录原配置和症状；不擅自关代理作对照，以免其他会话暴露或中断 |
| 静态 | 当前核心 -t、引用／顺序／DNS 依赖；只能证明可解析 |
| 运行 | mode、TUN／严格路由、当前组选择、目标规则链 |
| 候选 | 逐节点公开 HTTPS／实际 VPS 端口链路；延迟成功不等于中转能到落地 |
| 业务 | TLS、目标出口、实际链路；需要登录时用户参与，不用付费 API 当默认测活 |
| DNS | 浏览器深度检测与上游路径；有歧义时经授权限定抓包，不能承诺零泄漏 |
| IPv6／UDP | 针对症状分别查本机与远端、WebRTC／UDP；未测则注明 |
| 回退 | 主失效、备用、主恢复、全失效；优先独立组／隔离环境，替身测试注明范围 |
| 持久性 | 重载／获准重启后重查；不为测试强制升级或刷新收费订阅 |
| 恢复 | 备份可读、路径明确；失败时实际恢复并验证。区分可恢复性检查与已实际恢复 |

独立测试第二个核心时，考虑现有 TUN 会否再次代理它，避免把双重代理结果当成独立出口。生产核心临时诊断入站仅绑定回环，属于运行变更；仅在授权内使用，并通过可靠清理路径恢复正式配置和移除测试节点／端口。

## 可用交付

### WSL／CLI 分支

浏览器通过但 WSL／CLI 失败时，按以下依赖顺序检查，不先改 Windows 防火墙或代理监听：

1. 确认具体发行版、CLI、执行位置和版本；只读核对 WSL 版本、用户的 .wslconfig 中网络模式，以及发行版的路由／resolv.conf。不遍历整个 Linux 家目录。区分 NAT、mirrored 和版本支持，查 [WSL 网络文档](https://learn.microsoft.com/en-us/windows/wsl/networking)。
2. 在 CLI 实际进程环境检查 HTTP_PROXY／HTTPS_PROXY／ALL_PROXY／NO_PROXY 及小写形式，只输出是否存在和脱敏后的协议／端口；不要打印带密码 URL。父 shell 变更未必被已经启动的 CLI 继承。
3. 核对宿主代理绑定。mirrored 在支持条件下可使用宿主 localhost；NAT 下 Linux 的 127.0.0.1 通常指向自身，Windows 网关／宿主地址需据当前路由确定。代理只监听宿主回环时，不能假设它能经网关访问；不要为解决问题擅自开放 LAN 或绑定 0.0.0.0。
4. 先从 WSL 实测可达的宿主代理地址，再用同一地址访问公开 HTTPS 目标，分别区分 TCP 不通、DNS 失败、TLS 错误和 HTTP 拒绝。记录请求到底由 Windows TUN 还是显式 HTTP 代理接管。
5. 需要改变监听、Hyper-V／Windows 防火墙、WSL 网络模式、持久代理变量或执行 wsl --shutdown 时，先核对授权和其他工作负载；保持最小暴露，采用当前版本支持的方案。autoProxy 等功能依 WSL 版本及模式核实，不能保证已有 Linux 进程自动更新。
6. 最终在实际 CLI 新进程验证目标路径和规则链。未登录／未调用付费 API时，只报告网络验证，不能宣称产品全部可用。

记录版本、症状、证据／推断、最终文件、备份版本、测试／未测项、日常选项、恢复命令和更新后复查点。含 IP 的截图／日志只在已授权本机保存，不上传完整配置。

用户应知道：全局还是规则模式；AI 用哪个组；怎样恢复自动选择；手动节点的影响；全失效行为；怎样回到修改前。CLI 代理变量、NO_PROXY、WSL／容器单独核对，浏览器通过不能代表它们通过。
