# 从首次提问到交付

用于新手将网络配置交给 agent 的场景。共同权限与会话保护规则以 [SKILL.md](../SKILL.md) 为准；本文规定每阶段需要的证据，具体操作按发现的软件和可用工具选择。

## 步骤编号与进度提示

先按本轮目标选择适用步骤，首轮消息展示全部编号、总数和当前状态。以下八步是“检查、配置并接入持续守护”的完整模板，不是所有请求的必做清单：

1. 确认目标与权限。
2. 检查环境与工具能力。
3. 采集基线并定位问题。
4. 准备方案、备份和校验候选。
5. 应用配置并核对实际生效。
6. 完成网络、故障及恢复验收。
7. 接入持续守护并验证采集与处置。
8. 交付使用入口、剩余项和恢复方法。

只读诊断可合并为四步：确认目标与权限 → 检查环境 → 采集证据与判定 → 交付结论。只做仓库文档维护可用三步：核对资料 → 更新文档 → 校验交付。用户不需要持续守护时删去该项再连续编号；尚未授权的登录、系统修改或真实故障注入只列为待决定事项，不偷偷编入已授权执行范围。

统一使用以下状态：**待进行、进行中、已完成、受阻、不适用**。只有有证据满足该步完成条件时才记“已完成”。检测自身的“通过／失败／未知／未测”另外标明：采集步骤可以完成并得到未知结果，要求证明安全的验收步骤则不能因采集完成而通过。交付清楚的未知结论可完成诊断任务，但不能宣称相关防护已经验收。

每进入新步骤、完成步骤、发现阻碍或进入本轮后续对话时，在普通会话里主动报告进度。较长步骤按需要展示子项，如“第 6 步验收：6.1 HTTPS 已通过，6.2 WebRTC 未确认，6.3 实际 Code 会话未测”。读文件、单个命令和重试不单独增加总步数。失败后的恢复属于当前步骤的子项，除非目标确实发生变化。

提示示例：

```text
本轮共 8 步，已完成 5 步。
正在第 6 步：网络、故障及恢复验收。
已验证：专用 HTTPS 入站和出口。
尚未完成：WebRTC 结果判定、恢复验证、守护接入和交付。
实际 Claude 会话：未测；按你的要求保持不启动。
```

示例内容必须由本轮证据替换，不能复制成实际进度。步骤序号不是完成百分比，也不代表可靠的剩余时间。没有依据时不估计多久完成。

跨轮继续时保留计划、编号、完成证据和剩余检测，不重复执行已完成的修改。目标变化需要增删步骤时说明原因，展示更新后的完整列表和总数；映射原有已完成项，不把新增步骤倒填为完成。长任务将进度保存在使用者私有记录中，不写入公共样例作为下一用户的初始状态。

结束时给出“已完成 K/N 步”，列明受阻／未进行的步骤、未测项与下一步动作；若有尚未满足的强制验收，就按实际交付部分结果，不能报告 N/N 全部完成。只维护文档时明确未执行网络复测，不能让用户误以为旧的网络证据已更新。

定时守护无变化时仍保持安静，不逐步推送例行轮询。仅有需通知的变化时，说明本轮已执行到哪一步、采取了什么动作及还缺什么；不创建新的重复任务来展示进度。

## 1. 确认目标与权限

先利用会话已有答案，只问尚未决定且会改变方案的问题：

- “这次允许只读检查，还是允许备份后修改并重载代理客户端？”
- “想保护所有流量，还是指定应用？目前哪里不正常？”
- 需要独立线路时再问：“原线路不可用后，允许切换同地区备用，还是立即停止连接？”

未确定地区、Claude 入口或需要保护的现有会话时，补问相应事项。不要默认所有用户都需要新加坡，也不要让新手先提供配置路径、管道名或控制端口。先解释影响，再请用户做选择。

进入本机检查前应已有对应授权。授权记录只记录用户实际决定，不从样例默认值推断同意。

## 2. 检查环境与能力

在授权内发现客户端、内核、版本、配置来源和实际运行状态。确认代理模式、监听端口、DNS／TUN 和目标应用执行位置。仅读取任务所需字段，凭据留在进程内。

同时确认终端、浏览器、依赖和本机控制接口是否可用。接口不存在、权限受限、服务没运行是不同问题。缺少能力时完成可做的检查，并写明无法完成的步骤。

持续守护使用公开 v2 适配器，仍需本机私有配置和正式浏览器／调度接入。按 [可移植守护](portable-guard.md) 初始化、部署和验收；不得把其他机器的私有部署脚本或样例路径当成已安装组件。通用配置工具见 [工具说明](tool-workflow.md)，常见误判见 [踩坑记录](lessons.md)。

## 3. 采集基线并定位问题

分别记录用户症状、实际检测、运行配置和未知项。公网 HTTPS 出口不能替代 WebRTC、DNS 或实际应用链路。用户截图是历史证据，不能冒充刚执行的现场检查。

逐项记录 HTTPS、DNS、IPv6、WebRTC 与目标应用链路的适用性和证据状态，说明哪些检测尚未完成。只读诊断到证据判定后即可交付，不进入应用配置步骤。

## 4. 准备方案、备份和校验候选

提出与目标相符的最小改动，说明影响范围、回退条件和需要重新登录或重启的部分。只询问仍缺少的授权；已有授权足够时继续准备候选，不把必要工作留到下一轮。

用户希望优先同一节点或下一步直接启动桌面应用时，读 [防护范围与启动检查](protection-and-startup.md)，准备固定首选／有序备用及范围明确的启动预检。不要以普通 Fallback 代替泄漏检测，也不要把网页入口当成桌面入口。

完整备份存于用户本机私有位置，记录修改目标和恢复对应版本。解析配置、生成候选、运行当前内核校验后再应用。具体文件事务用 [工具流程](tool-workflow.md)。

## 5. 应用配置并核对实际生效

通过实际客户端支持的方式保存与重载，核对运行核心、磁盘文件与 UI 是否一致。不能只修改生成配置后就宣布持久生效。

应用失败先进入恢复子步骤，核对文件、运行核心与必要选择，标明恢复已完成还是待核查。恢复未确认时不跳到“配置完成”。

## 6. 完成网络、故障及恢复验收

| 改动 | 至少需要的证据 |
| --- | --- |
| 代理模式或分流 | 实际模式、目标连接链和预期入口／出站 |
| 独立线路 | 专用入口确实命中，未落入普通 GLOBAL 链 |
| WebRTC 处理 | 同一浏览器中实际 STUN 结果；无候选保留未知 |
| 回退或换出口 | 候选连通、地区与实际出口符合约定；模拟与实际动作分别记录 |
| 暂停保护 | 精确实例身份、暂停与恢复数量、其他实例排除、异常退出后的行为 |
| 持久配置 | 按授权重新生成／重载后的核对；未测重启就明确未测 |

需要真实登录或付费请求时，不用已有账户静默补测。修改导致失联时优先恢复，验证基本网络后再决定是否继续。

## 7. 接入持续守护并验证采集与处置（可选）

只有用户要求持续检测时才配置。确认检测源、真实触发条件、未知结果、单次切换预算、失败动作及实例范围，明确采样间隔和不可运行的条件。

部署前必须具备真实浏览器采集、经验证的路由适配器、状态持久化、调度入口和手动恢复。策略单元测试通过不等于接入完成。先用独立模拟状态驱动获准的实际动作，再重新采集真实页面，确认演练已清理且正式状态没有混入模拟事件。

在支持会话定时任务的环境中使用正式调度工具；工具不可用则说明未部署，不偷偷安装系统服务作为替代。无变化时保持安静，故障或需用户操作时才通知。用户明确关闭的应用不为检测自动重开。

## 8. 交付使用入口、剩余项和恢复方法

报告当前模式、改动、实际测试与未知项、备份和恢复入口。说明日常应该打开哪个入口、错误时怎么停用，以及哪些操作会绕开所配置的保护。

先自行补齐已授权的必要实施和验证，再交付。完成后推荐复测或查询状态即可，不为延长对话制造新任务。现场记录留本机；可复用经验提炼到 [踩坑记录](lessons.md)，保留适用条件和证据层次。
