# 防护范围、固定主节点与桌面启动检查

用于解释已有防护能应对什么，或在用户要求稳定出口、桌面专用入口时准备方案。通用部署读 [可移植守护](portable-guard.md)，实际接入读 [Claude 独立链路](claude-dedicated-route.md)。先复用会话授权；整理文档不授权检查或修改本机。

## 已完成内容与证据层次

以下是截至 2026-10-26 已记录的实现与验收，不是每次读取本文都重新执行了现场检查。场景中的新加坡、主节点、间隔和过期阈值是使用者的选择，不是其他用户的默认配置。

2026-10-27 已新增 [独立本地采集与启动时刷新](native-guard.md)。原先等待 agent 定时采集的桌面原型已在本机改为启动时自动刷新；当前采集和失败暂停范围迁移到新建无账号的隐藏检测实例，原可见浏览器不再是采集依赖。以下历史表格不能替代这次运行方式变更说明。

| 任务／防护 | 能应对的情况 | 已有证据及限制 |
| --- | --- | --- |
| 代理环境盘点、DNS／TUN／IPv6 路径辨认 | 配置文件、系统代理和实际核心不一致；把 HTTPS 出口当作所有协议证据 | 有现场诊断及离线工具；不能从 TUN 开启或 DNS 劫持单项推出全流量无泄漏 |
| 全局模式下的回环专用 HTTP 入站 | 指定应用需要独立链路，不随 GLOBAL 的日常选择变化 | 现场公开 HTTPS 请求已验证专用入站／守护组，无 GLOBAL 或 DIRECT；不证明桌面实际会话 |
| 固定主节点优先、同地区有序备用 | 不希望按延迟频繁换出口，同时允许主节点失效时回退 | 现场四个候选测到同地区、不同出口；应用前后主节点和生产出口相同，GLOBAL 未变；没有据此宣称真实生产故障注入已验收 |
| 隔离浏览器与 WebRTC 候选限制 | 避免复用已有登录资料；专用浏览器的 STUN／UDP 路径需要单独验证 | 实际九行页面可采集；无候选保留 unknown，浏览器参数不能推广为桌面行为保证 |
| 实际泄漏触发、单次换线、同页复测 | STUN 结果出现已登记历史宽带 IP；备用必须同地区且实际出口不同 | 策略及集成分支有测试；真实无候选采集不会触发。普通 Fallback 健康检查不算泄漏检测 |
| 失败拒绝入口、精确 Edge 暂停、手动恢复 | 换线无法验证、复测仍泄漏、动作中断或重复执行 | 有独立演练及原生暂停／异常退出恢复记录；暂停范围仅为隔离 Edge，不能撤回已暴露数据 |
| 定时采集与过期状态 | 检测停止、浏览器断开、任务丢失，避免持续使用旧结果 | 本机已恢复正式定时任务并完成后续实际采集；依赖电脑、agent 和浏览器在线，非实时系统保护 |
| 桌面专用启动前检查原型 | 代理不可用、检测过期、失败状态未恢复、已有 Claude 进程、安装版本改变 | 本机六项离线测试、真实过期拒绝及更新采集后预检通过；未用启动 Claude 补测 |
| 备份、回滚、通用化及脱敏候选 | 变更失联、需要恢复、人工后来修改、避免把私有配置打包 | 公共工具干净副本有 61 项 Python／15 项 Node 测试通过；新电脑真实部署与实际 Claude 会话仍未验收 |

公共仓库已有可移植守护 v2 代码。固定优先顺序的本机适配、桌面启动器和快捷方式仍属于使用者私有部署，本节提供可复用的准备规范，**没有随仓库提供一个已验收的通用桌面启动安装器**。agent 必须按实际客户端实现并测试，不能引用某台电脑的私有文件作为公开依赖。

## 用户希望每次优先同一节点

先区分“固定主节点、允许故障备用”与“严格固定路径、失败就停”。前者可使用固定顺序 Fallback；后者不擅自加入自动回退或泄漏后换线。节点名称不保证地区、实际 IP、机房归属或线路独享，保留这些区别。

用户已允许回退时：

1. 发现当前实际物理节点，核对它在批准名单内并验证出口；若当前线路符合目标，优先保留，避免部署本身造成换出口。
2. 用独立探测入口核对备用的连通性、地区和实际出口，保存原探测选择并在 finally 恢复。需要不同 IP 的备用不能只比较节点名字。
3. 将首选节点放在 Fallback 的第一位，后面是固定顺序的已验证备用；不改成 url-test、负载均衡或每次启动测速选最快。
4. 备份并更新持久扩展和候选配置，用实际核心校验。上层守护 Selector 选择 Fallback 后才会启用普通健康回退；先确认它实际落到预期首选，再核对生产出口和 GLOBAL 没有意外变化。
5. 说明主节点故障时允许换出口，恢复后可能回到首选。若用户希望切到备用后一直保持，应另行确定这种保持策略，不能声称普通 Fallback 已提供这一保证。

选择关系示例，名字由本机发现，不作为固定默认值：

```text
专用入站 → 守护 Selector → 专用 Fallback → 首选节点／按序备用
                         → 事件内指定备用节点
                         → REJECT（失败处置）
独立探测入站 → 探测 Selector → 待验证候选
```

正常与未知结果不重设节点；泄漏事件内的单次换线也不因下一轮定时执行而自动回到首选。探测组不作为日常业务入口。不要仅凭 UI 中出现多个组就要求用户逐个手选节点。

## 不改共享设置的桌面启动候选

只在用户确实要求专用桌面入口时准备。先发现实际安装与版本、普通快捷方式目标、用户／机器环境和允许的配置键；不启动版本命令、不读取 Cookie 或认证文件、不解密保存环境。查 [当前官方网络配置](https://code.claude.com/docs/en/network-config) 与 [桌面环境说明](https://code.claude.com/docs/en/desktop#environment-configuration)，区分本地、桌面管理提供方、云端、SSH、WSL 等作用域。

用户禁止共享配置变更时，可以准备仅由新进程继承代理环境的包装入口，以及实际版本支持的桌面代理参数。复制启动器自身环境到新对象，在该对象内统一需要的大小写 HTTP／HTTPS 代理值，检查 NO_PROXY 是否绕过保护域名；不写机器变量或共享 settings，不复制登录 profile。Electron 参数、ALL_PROXY 和 WebRTC 参数不能当作所有桌面组件均支持的证据；SOCKS 和各会话作用域按厂商说明核对。

启动器应具有独立的只检查模式；它验证以下事实后，才能由用户主动启动目标应用：

| 检查 | 不满足时的行为 |
| --- | --- |
| 已有 Claude 或 Code 进程 | 拒绝把新参数交给旧进程；用户自行保存／退出，不自动杀进程或重启 |
| 目标程序和安装入口身份／版本符合已核对记录 | 软件更新后要求重新核对；不无条件使用遗留旧版本 |
| 守护启用，未处于切换、暂停、恢复待定状态 | 保留失败状态，拒绝启动；不自动 resume 或 enable |
| 真实采集时间有效、通道已验证 | 过期或不可确认时拒绝；阈值与采样间隔配套配置，不能重打旧结果时间 |
| 用户约定的模式、TUN 和专用入口存在 | 报告实际不符合的条件，不为了放行启动而自动改配置 |
| 实际选中节点属于批准名单，公开出口可达且地区符合目标 | 拒绝启动；不借检查之名轮换生产节点或放宽名单 |

本机原型采用五分钟采样、七分钟过期阈值。它允许“通道已验证、采集新鲜，但九项无候选”的 unknown 满足预检条件，因为用户选择以实际基线命中作为换线依据；这不是安全判定。另一用户要求 unknown 时阻断，必须按其要求设计，不能复制本机放行逻辑。

至少验证：只检查模式从不启动；失败不启动；已有进程／版本改变被拒绝；代理环境仅作用于新进程；模拟成功分支形成正确参数。再以真实过期输入拒绝、真实新采集恢复预检做无登录验证。不要故意断开整条生产网络或启动旧登录会话完成测试。日志只记录必要摘要，避免凭据和完整浏览记录。

交付时给出可辨认的桌面图标名、目标及失败提示。网页专用浏览器快捷方式与桌面启动器要明确区分；默认 Claude 图标没有自动获得新入口的检查。用户下一步已经明确要启动时，直接交付可用入口和边界，不再让用户重复发送“继续准备”。

## 应对故障的范围

- **节点故障**：Fallback 的普通健康回退负责可用性，不负责判定泄漏。固定节点仍可能被供应商分配新 IP。
- **真实基线暴露**：按既定单次预算换线并同页复测；失败拒绝入口并暂停准确的隔离 Edge。不要在未知结果上重试换线。
- **检测中断**：检查采集时间、浏览器连接和正式任务是否仍存在。先复用已有任务；确认任务不存在且用户已要求恢复时才恢复单个任务，不猜测是用户删除，也不重复创建。调度标记 ACTIVE 不等于已完成一轮真实采集。
- **守护崩溃**：持久意图与日志支持下一轮 recover，避免重放动作；不确定事务仍需核查，不能自动解除暂停。
- **桌面启动条件失效**：启动前拒绝能防止在已知异常状态下新开应用；它不持续监督启动后的所有请求。代理退出后的保护和桌面进程暂停不属于现有 Edge 执行器能力。

即使桌面采用同一专用 HTTP 入口，REJECT 也只能限制经过该入口的连接，不能推广到旁路协议、已提交 I/O、MCP、开发服务器或远端执行。需要桌面或系统级失败即断网时，另行设计并验收精确隔离／防火墙范围；文档维护不授权部署这些措施。

首次实际 Code 会话的连接链只能在用户明确开始会话后观察。预检通过、公开端点 404／403、STUN 全绿、TUN 开启或已有截图都不能替代该证据，也不能保证账号审核或业务可用性。
