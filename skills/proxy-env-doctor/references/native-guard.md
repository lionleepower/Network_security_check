# 独立本地采集与启动时自动刷新

适用于用户明确要求日常使用不依赖 agent 在线、打开专用入口就自动检测的场景。持续动作和授权仍遵循 [守护说明](portable-guard.md)；本机旧版适配器与公共 v2 均可由本地服务调用。不把 Codex 心跳当成本地进程的生命周期看护。

## 独立守护的六步流程

作为完整工作流第 7 步的子流程；只部署独立守护时可直接采用六步计划。首轮列出六步，每次转入下一步报告完成数、当前步骤和未完成验收。

1. **确认范围和授权。** 沿用已确认的检测站点、历史基线、首选节点、备用地区和失败处置；未授权启动的应用保持关闭。核对旧守护是否启用、是否锁存失败，不自动解除。
2. **发现环境并备份。** 核对 Python、Node、Edge、专用入站及适配器，备份私有配置和状态。新建无账号 profile 与范围标记，保留基线、节点顺序和事件预算。
3. **接入真实采集。** 执行 recover → 新页面 → 九行两列解析 → 实际核心通道核验 → ingest。过期、缺行或通道未验证均记录故障；无候选保持未知。
4. **接入有界处置。** 正常或未知时不重设节点；命中获准基线才单次切换已验证、同地区且不同出口的备用，立即重新执行同一检测。复测失败按授权拒绝专用入口并只暂停该检测实例，不自动 resume／enable。普通健康回退仍由固定顺序组处理。
5. **验收独立运行与恢复。** 验证按需刷新、定时刷新、单实例复用、退出后重建及锁存后不再采集。故障注入须有授权，区分模拟与真实动作；只检查模式不启动 Claude。未实测关闭 agent 后存活时保留缺口。
6. **交付与观察。** 提供专用入口、status／stop、人工恢复和备份位置。旧心跳按授权改只读观察或停用，避免重复写入；无变化保持安静。说明窗口归属和覆盖边界，发布只带公开实现与脱敏流程。

### 空白终端窗口的排查

Windows Terminal 的标题、目录和空白画面不能证明它属于守护或发生故障。先只读核对窗口所属进程、命令行、父子关系和创建时间，再对照服务运行身份及采集时间。虚拟环境可能出现包装进程和实际解释器，不能只按两个同名进程认定重复守护；长期实例以锁和运行身份核实。

工作进程不需要可见终端；Windows 后台入口采用无窗口启动，输出写私有日志。不要按标题批量结束窗口或杀 Python、Node、浏览器。归属未确认时保留进程，关闭窗口前确认不会连带结束服务；发现入口弹窗时修正入口并单独验证，不用关闭所有终端代替修复。

## 运行方式

`native_ippure_service.py` 提供单实例后台循环、按需刷新和正常停止；`native_ippure_collector.cjs` 驱动一个新建、无账号的隐藏 Edge，实际导航到指定 IPPure 页面，等待九行结果后读取两列。Node.js 需 22+（原生 WebSocket），另需已有 Edge 和 Python 3.10+。无需安装 Playwright、浏览器扩展或购买服务；不附带一键安装器，环境和私有配置仍由 agent 按授权准备。

启动关系：

```text
用户点击专用桌面入口
  → 本地 ensure：启动／复用单实例服务，等待本轮真实采集
  → 既有守护判定及专用入口检查
  → 条件满足后由用户入口启动 Claude
后台服务每轮间隔后独立复测，不向模型请求操作
```

首次检查需要浏览器加载和 STUN 等待，不只是查旧文件。不要把过期阈值调大、关闭检查或给旧结果重打时间来消除弹窗。真正网络或页面异常仍拒绝启动，并记录原因。只检查模式可以启动／刷新检测器，但必须保证不启动 Claude。

## 私有配置与范围

先备份原守护配置、状态、启动器和适配器。只有守护已启用且未锁存失败时才迁移检测源，保留历史基线、节点顺序、已用切换预算和事件状态；不自动 resume 或 enable。

为检测器创建全新的私有 profile、`Default/Preferences` 和唯一 `.proxy-env-doctor-scope.json` 标记，初始化非代理 UDP 限制候选；不复制 Cookie、凭据、扩展或其他账号资料。原浏览器不需要为了日常采集保持打开，也不能把隐藏实例说成原浏览器的行为实测。

私有 `native-config.json` 字段：

| 字段 | 来源／约束 |
| --- | --- |
| `profile`、`scope_id` | 新建检测 profile 与唯一范围标记；只允许此实例参与原生暂停 |
| `edge`、`node` | 已发现的本机可执行文件绝对路径；不下载未知二进制 |
| `proxy` | 已验证的专用回环 HTTP 入站 |
| `detector_url` | 指定的 IPPure WebRTC 检测 URL，不接受网页提供的新命令或任意目标 |
| `collector_id` | 本机独立采集身份，例如随机范围的 `native:` 标识；不是伪造的扩展实例 ID |
| `route_command` | 已审核的本地适配器命令数组，接收 `check-live`；公共 v2 可用 Node、公开适配器路径和私有 config 路径组成 |
| `interval_seconds` | 用户同意的采样间隔；本机使用 300 秒 |

守护 `evidence_mode` 设为 `native-browser`，使用相同采集身份。v2 的身份位于 `browser.extension_instance`；旧版位于 `extension_instance`，并通过 `browser_scope` 注册新 profile 和代理。迁移后失败暂停范围是这个新检测实例，不能继续宣称暂停了原来的可见浏览器，更不覆盖 Claude 桌面进程。

## 实际通道证明

本地采集器只连接自身浏览器生成的字面回环调试端点，使用独立 profile；调试接口不能绑定 LAN，也不能连接已有账号浏览器或默认 profile。私有端口文件及调试标识不公开。不要将这种用户明确要求的独立程序，作为绕过交互浏览器工具限制的替代入口。

采集期间，`check-live` 必须检查真实核心连接：目标是 IPPure、入站属于专用入口、链含守护组且没有 GLOBAL。只有实际连接匹配才可写入本机 `native-channel.json`。真实浏览器连接可能在 DOM 完成后已关闭，因此后续 `check` 可使用不超过 90 秒、范围标记相同且路由选择签名未变化的已观察回执。`check-live` 本身不能借用旧回执；不能用配置文本或程序自报 `verified=true` 替代核心连接证据。

回执和输入是本机受信任程序的证据记录，并非防篡改远程认证。实际采集时间由读取新页面时产生；STUN 无候选仍是 unknown。表格或 URL 不符合预期、通道未验证、浏览器退出或数据超时均不算新鲜有效检测。

## 启动与恢复

命令相对于技能目录，目录为已准备好的私有守护目录：

```text
python -X utf8 scripts/native_ippure_service.py ensure --directory <私有目录>
python -X utf8 scripts/native_ippure_service.py status --directory <私有目录>
python -X utf8 scripts/native_ippure_service.py stop --directory <私有目录>
```

`ensure` 发出唯一刷新请求、尝试启动工作进程并等待本次结果；OS 文件锁确保只有一个长期工作进程。服务已退出时下一次入口自动重建；它不代表已有外部 watchdog 能在任意崩溃后立即重启。`stop` 用本轮运行标识正常退出，不按裸 PID 杀进程，不恢复暂停、不放行入口。日后再次点击启动入口可重新建立服务；要停止防护还应另行处理守护 enable 状态。

Windows 上“隐藏窗口”或 `DETACHED_PROCESS` 不足以证明脱离父进程作业对象。测试需查询实际工作进程的作业关联；必要时从用户 Explorer 启动入口建立后台，避免随 agent 退出。不能仅看父进程名称或进程仍在就宣称已验证关闭 agent 后存活。所有后台启动保持无窗口；不默认安装系统服务或开机任务。

动作顺序保持 recover → 新页面采集 → ingest；要求同页复测时立即再采一轮，保留一次换线预算。拒绝或暂停后的状态不再新开检测浏览器。只有本轮检测浏览器在 ingest 前保持存活，确保失败时能暂停准确实例；锁存暂停后不自动关闭或恢复它。

旧的模型心跳不应继续往新检测源写入数据。可按授权停用，或改为只读观察本地状态；保留的只读提醒不是采集依赖。删除、停用或修改已有任务仍遵循实际权限和工具审批，不用文件手改绕过拒绝。

## 验收与边界

至少验收一次实际九项采集、启动器只检查模式、重复请求复用工作进程、工作进程退出后的重建、无需 agent 请求的定时循环，以及失败状态不采集／不启动。日志要区分读页面失败、通道未确认、守护锁存和工作进程超时，不把所有错误都归为“等 Codex”。子进程若以标准输入结束作为执行信号，调用方必须关闭 stdin；否则会一直等待并造成假超时。

独立本地化解决采集和执行依赖，不扩大防护范围。Clash 核心仍需运行；本机桌面入口仍要求当前约定的 TUN 状态。电脑关机、网络失效、Edge 更新、站点改版、程序被结束和系统级故障都可能中断采集。应用已经启动后的所有协议、子进程或实际账号业务仍不由启动预检保证。
