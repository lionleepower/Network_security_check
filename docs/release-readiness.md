# 面向新手的 GitHub 发布准备

目标是用户下载项目后，交给有相应工具的 agent，回答少量目标与授权问题，就能完成受支持范围内的检查、配置、验收和恢复。

## 发布内容的分工

| 内容 | 职责 |
| --- | --- |
| README.md | 新手入口、可复制请求、实际支持范围 |
| AGENTS.md | 让打开仓库的 agent 找到技能和维护规则 |
| SKILL.md | 技能识别、权限边界、参考路由 |
| references/workflow.md | 阶段、分支、通过条件和停止条件 |
| references/lessons.md | 集中的通用踩坑记录 |
| scripts/ 与测试 | 可重复执行的实现与验证 |
| 使用者本机私有目录 | 授权记录、现场证据、实际配置、状态和备份 |

保留一个入口和一份踩坑记录，详细实现按主题分文件。完整聊天日志和机器信息不进入公开技能。

## 当前发布候选状态

| 项目 | 状态及边界 |
| --- | --- |
| 公开路由适配器 | 已实现本地接口、独立探测、同地区不同出口的单次切换、拒绝入口与旧连接清理；离线控制器和回环 HTTP 测试 |
| 私有配置与默认值 | schema v2，默认停用、无授权、无真实基线；地区、节点、端口、profile 和浏览器实例由 agent 按授权发现并验证 |
| 安装和恢复 | 已提供初始化、只读发现、核心校验、安装回滚、手动恢复及卸载；安装测试使用模拟核心，尚无新 v2 真实部署验收 |
| 干净副本 | 按白名单复制，使用新虚拟环境与声明依赖执行测试；验收记录随本地候选交付，不依赖私有适配器 |
| 真实采集与调度 | 支持 agent 流程，以及 Node 22+／Edge／Python 的独立本地服务；需按机器配置私有入口和检测范围，无新电脑真实部署验收 |
| 原生实例暂停 | 支持 Windows Edge 精确范围；新 v2 参数化路径已离线验证，旧版现场证据不推广为所有环境通过 |
| 固定首选与桌面预检 | 已补公开操作规范和证据边界；固定顺序的本机适配、桌面启动器／快捷方式仍是私有原型，未随公共包提供通用桌面安装器 |
| 许可证 | 作者尚未选择，本次源码同步不擅自添加许可；公开可读不代表已授予开源再分发许可，正式开源发布仍需作者决定 |

这是一份实验性发布候选，不是“所有新电脑开箱即用”的认证。真实新电脑安装、订阅重生成、独立故障演练、调度离线告警和实际 Claude 会话仍须单独验收。保持 Claude 不启动也能完成本次源码候选验收。

## 发布时检查

1. 用 `git status`、`git diff --cached` 和文件清单核对发布内容。忽略规则不会撤回已跟踪文件或清除历史泄漏。
2. 检查暂存内容和相关 Git 历史中的凭据、订阅链接、真实 IP、用户名路径、浏览器实例标识及备份。若真实凭据已进入历史，先处理失效和历史清理，不能只删最新文件。
3. 只选择 README、AGENTS、docs、skills、依赖声明和 CI 等公开内容；不压缩整个工作目录上传，不强制添加 reports 或私有目录。
4. 在没有本机私有脚本、备份、已安装同名技能和现成虚拟环境的副本上验证文档、依赖和测试，不借助开发者机器上的隐藏文件补齐验收。
5. 根据实测写支持范围，区分离线测试、模拟信号触发真实动作、真实网页及实际登录会话验证。发布不自动授权启动、登录或修改账号。

## 新手验收场景

| 场景 | 期望结果 |
| --- | --- |
| 只有项目，没有运行环境 | 说明缺什么并完成独立分析，不静默安装或假报通过 |
| 用户只授权只读 | 不改代理，交付证据、问题和建议 |
| 用户授权配置支持客户端 | 发现入口，备份、校验、应用、核对和恢复方法完整 |
| 已有 Claude 登录会话 | 保留会话，用授权的独立检测上下文 |
| IPPure 无候选或表格变化 | 未确认，不误换线、不解除失败暂停 |
| 备用与原线路同 IP | 不算有效换出口，按失败策略处理 |
| 切换中断、重复触发、PID 重用 | 不重复生产换线、不操作错误实例，报告需恢复或核查 |
| 浏览器关闭、调度不可用或工具拒绝 | 记录检测缺口，通知有意义变化，不绕过限制 |

完成这些场景后再决定将持续守护列为正式能力。文档整理和当前本机演练不能替代这一步。

## 构建和复核

在仓库根目录执行以下命令，输出目录必须是新的：

```text
python -X utf8 skills/proxy-env-doctor/scripts/build_release.py --output .release/rc-new
```

工具只收集根文档、依赖、docs、技能和 CI，拒绝符号链接、未知类型及部分高置信度敏感模式；生成 source、逐文件 SHA-256 清单、ZIP 和归档校验值。模式扫描不能发现全部密钥／IP／实例标识，必须结合人工审查。ZIP 不含 Git 历史，不等于原仓库历史已脱敏。

在候选 source 内用新的虚拟环境安装 requirements-dev.txt，执行 validate_skill.py、Python unittest discover，以及 Node 的 test_runtime.cjs 和 test_mihomo_guard_adapter.cjs。CLI init 另用版本库外的新私有测试目录，确认 draft／enabled:false 且 ready 校验拒绝。删除或归档测试目录前确认路径，不改生产目录。将实际命令、版本、数量、限制记录在候选旁，不夹带本机绝对路径。

发布前检查本次暂存区及所有可达 Git 历史；扫描输出只保留位置和类别，不打印敏感原文。若历史有真实凭据，先按授权处理，不通过“忽略目录”掩盖。当前构建工具不会 git add、commit、push 或上传，发布仍是单独操作。
